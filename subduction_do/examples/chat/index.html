Subduction on Cloudflare Durable Objects

A standalone example client for the Subduction sync service. Every message is a signed commit synced through a hibernatable Durable Object. Open this page in two tabs (or two browsers) and watch them converge — the DO can evict itself between messages and rehydrate from SQLite. Point it at a service with ?server=ws://127.0.0.1:8787.

How it works: each tab builds a Subduction client (a fresh in-memory Ed25519 identity + in-memory storage), performs a signed handshake with this document's Durable Object over /sync/<doc>, and subscribes to the shared document. There is one Durable Object per document, each with its own SQLite. New commits are pushed to subscribed peers; the DO fans them out inline before hibernating, persists commits + subscriptions so nothing is lost across evictions, and runs an on-demand alarm to expire replay nonces and compact redundant data. Messages are chained into a commit DAG, and every few messages the client sediments the run into a signed fragment — which is exactly what the DO's alarm compacts the now-redundant loose commits down to.
