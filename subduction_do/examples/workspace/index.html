Subduction · workspace multiplexing benchmark

Measures the cost of bringing an N-document workspace online for a fresh client under two routing topologies against the same Durable Object service:
• Multiplexed — one WebSocket to /sync/<workspace>, every document synced over that single socket.
• Per-document — one WebSocket per document (/sync/<doc>), today's default.
Same engine, same wire protocol — only the routing key and the client's connection grouping differ. Point it at a service with ?server=ws://127.0.0.1:8787 (defaults to same-origin).
Set N and hit Run benchmark. Each run uses fresh random document ids (and a fresh workspace id), so no run benefits from another's already-synced state. The first run also pays Durable Object cold-start.

Live room · resilient multiplexing

Two peers — a writer and a reader — each hold one connection to a single room and multiplex 4 documents over it (via room-client.js). The writer appends a commit to a rotating document every ~2s; the reader receives them through the Durable Object's push to subscribers. Hit Sever & recover to drop the reader's socket — it re-runs the handshake, re-subscribes every document, and pulls anything missed during the outage, so no data is lost.
