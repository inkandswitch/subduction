Peer-to-peer sync for local-first apps

Subduction is a peer-to-peer synchronization protocol and library for CRDTs. It syncs encrypted, partitioned data between peers without a central server — efficiently, by comparing history metadata instead of shipping whole documents. Written in Rust, with bindings for the browser, Node, and a CLI.

What Subduction gives you

A sync layer for local-first software — bring your own CRDT, storage, and transport.

🪶

Efficient incremental sync

Sedimentree shards history into hashed layers, so peers diff compact metadata and transfer only the fragments that changed — not whole documents.

🔒

Encryption-friendly

Designed to sync encrypted, partitioned data. Peers can reconcile histories without decrypting the payloads they're relaying.

🌐

No central server

True peer-to-peer over pluggable transports — WebSocket, HTTP long-poll, or Iroh/QUIC. Any peer can relay; none is authoritative.

📦

Multi-platform

One protocol across native Rust, WebAssembly (browser & Node), and a CLI, so the same documents sync everywhere your app runs.

🧩

Automerge-ready

Automerge was the original target and ships as a first-class integration — but Subduction can carry any content-addressed data.

🪪

Verifiable identities

Peers prove an Ed25519 identity through a challenge/response handshake, and authorization is pluggable via policies (e.g. Keyhive).

Free hosted service

Sync for free on subduct.io

Don't want to run your own relay? Point any Subduction client at this domain and sync over WebSocket — no account, no key, no cost.

WebSocket endpoint
wss://subduct.io/sync/<room>

A <room> is any opaque key you choose. Every client that names the same room syncs together — use a document id to give each document its own room, or a shared workspace id to multiplex many documents over one connection.

  1. Open a WebSocket to wss://subduct.io/sync/<room> from any Subduction client (browser, Node, Rust, or the CLI).
  2. Handshake with the discovery service name subduction-do — both sides derive the same audience from it.
  3. Subscribe to a document to receive commits pushed by other peers in the room in real time.
  4. Sync — pull existing history and push your commits; the room relays them to everyone else connected.
// Browser client, via the subduction_wasm bundle.
import init, { Subduction, MemorySigner, MemoryStorage, SedimentreeId }
  from "@automerge/subduction";

await init();

const sync = new Subduction({
  signer: MemorySigner.generate(),
  storage: new MemoryStorage(),
  onRemoteHeads: () => render(),
});

const doc = SedimentreeId.fromBytes(docIdBytes);
const url = new URL("wss://subduct.io/sync/my-room");

// Handshake, then sync + subscribe to a document.
await sync.connectDiscover(url, "subduction-do");
await sync.syncWithAllPeers(doc, true, 5000);

⚠️ Before you rely on it

  • Open by default. Anyone who knows a room key can read and write it — treat room keys as unguessable secrets, or self-host with your own auth policy.
  • Not private. Bring your own encryption; don't put anything sensitive in a room on the shared service.
  • Not durable. Storage is uncapped and best-effort — data may be reset or deleted at any time, with no backups and no SLA.
  • Preview quality. Subduction is an early preview with an unstable API. Great for demos and experiments; not for production.

Want guarantees? It's open source — run your own with your own policy, storage limits, and identity.

How the hosted service runs

subduct.io packages Subduction's sync layer as a Cloudflare Durable Object — one hibernatable actor per room, each with its own SQLite.

🗂️

One object per room

The room key maps to a stable Durable Object, so load and storage spread across the fleet instead of piling onto one instance.

💤

Hibernates when idle

WebSockets stay open while the isolate is evicted from memory; connection and identity rebuild from storage on the next frame. You pay for work, not waiting.

💾

Durable & self-tidying

Commits, fragments, and subscriptions persist to SQLite, and an alarm compacts redundant history — firing only when there's actually work to do.

It's all open source — read the design, or deploy your own copy, in the subduction_do crate.
